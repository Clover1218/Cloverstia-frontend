## 文章页目录（TOC）模块

按用户要求做成「纸质书籍」体验：入口在文章标题下方一行，点击就地展开章节列表。

**方案选择**（用户拍板）：

- 收录范围：**h1 / h2 / h3**（用户说正文格式他自己调整，故兼容 h1）
- 开关：**不加** `features.toc` 配置项，所有文章默认开启

**新增文件**

**修改文件**

- `src/i18n/types.ts` + `src/i18n/lang/en.ts`：`post.tableOfContents = "目录"`（en.ts 里混中文是项目既有风格）

## 踩过的坑

1. **Tailwind `group-open` 的 group 必须放在 `<details>` 上，不能放 `<summary>`**。
   `group-open` 编译成 `:where(.group):open *`，要求 group 元素自身带 `[open]` 属性；
   `<summary>` 没有，所以写在 summary 上完全失效。正确写法：`<details class="group/toc">`。
2. **层级必须按实际最浅标题归一化**。最初用 `level = depth - 1`，
   导致《魔神之后》那种全篇 `##` 起头的文章，所有章节整体多缩进一级、顶层不顶格。
   改为 `level = depth - min(实际最浅depth)`。
3. 零标题文章必须条件隐藏入口（`奉承导师的信.md`、`有关我对AI生图的理论与实践理解.md` 都没有标题）。
4. 测试用临时文章时 `draft: true` 不参与构建，要验证必须写 `draft: false`；
   且 frontmatter 必填 `pubDatetime` 和 `description`，否则报 `InvalidContentEntryDataError`。

## 项目关键认知（复用价值高）

- **TOC 数据不用装插件**：`render(post)` 直接返回 `headings: {depth, slug, text}[]`，
  且 Astro 内置 `rehypeHeadingIds`（github-slugger）已给所有 h1~h6 生成 id，锚点天然可用。
- `remark-toc` + `remark-collapse` 已装但**完全哑火**（没一篇写了 `## Table of contents`），
  且不产出可编程访问的数据，做侧栏高亮这类交互用不了。
- 组件风格：Astro 组件 + `class:list`（不用 clsx）+ `class` prop 透传（不叫 className）
  + `size?: "sm"|"lg"` 联合类型；交互脚本写 `<script is:inline data-astro-rerun>`。
- Tailwind v4 CSS-first，**无 tailwind.config.js / postcss.config.js**，用 `@utility` / `@theme inline` / `@custom-variant`。
- 深色模式双轨：`<html data-theme>` 属性（防 FOUC）+ `.dark` class。
- 构建须用 `NODE_OPTIONS= ./node_modules/.bin/astro build`（项目记忆里的 genie-safe-delete 钩子会让 `dist` 清理超时）。
  改完代码要跑 `prettier --write`，printWidth 80 + tailwindcss 插件会重排 class。

## TOC 第二轮迭代（同日晚）

用户反馈三个问题，已全部修掉：

1. **去掉折叠栏右侧的章节计数**（`items.length`），箭头改用 `ms-auto` 撑到最右
2. **去掉底部「另有 N 个更小标题未列出」提示**，连同 `hiddenCount` 变量一起删除
3. **改成按宽度分栏**：默认单栏，`lg`（1024px）以上双栏

### 分栏方案选型（重要）

试过三种，**最终用 Grid 顺序填充**：
- **CSS `columns` 多栏**：❌ 会按高度均分，把一个章节的子标题拦腰截断到另一栏，
  目录这种需要顺序感的场景是硬伤。以后别用。
- **Grid 顺序填充**：✅ `grid-cols-1 gap-x-8 gap-y-0.5 lg:grid-cols-2`，
  左右并读，顺序不乱。
- 按章节分组（子标题不跨栏）：更完整但要重写渲染逻辑，当前没必要。

### 踩坑：Tailwind 类被去重

写 `grid-cols-2 sm:grid-cols-2 lg:grid-cols-2` 时，Tailwind 判定 `sm`/`lg` 变体
与基础类冗余，**响应式变体直接不生成**，结果双栏在手机上也生效（不是想要的）。
正确写法：基础类给单栏，只留一个断点变体 `grid-cols-1 ... lg:grid-cols-2`。

### 本项目验证 CSS 是否生成的方法（反复用到）

不要用 Bash `grep` 查转义类名（`\\:` `\\/`），**正则转义极易误报缺失**，
我因此连续两次误判「规则没生成」。用 node 直接读文件 + `indexOf` / 简单正则最可靠：

```bash
node -e "const css=require('fs').readFileSync('dist/_astro/Layout.xxx.css','utf8');
console.log(css.match(/\.lg\\\\:grid-cols-2\{[^}]*\}/))"
```
注意 CSS 文件名带 hash，要 `ls -t Layout.*.css | head -1` 取最新的。

## TOC 第三轮迭代：改用 CSS columns（同日晚）

用户明确要求**纵向排列**（先填满左栏再换栏）+ 中间加分隔线。
上一版用 Grid 是**按行横向填充**，方向错了。

最终写法：
```html
<ol class="columns-1 gap-x-8 lg:columns-2">
  <li class="break-inside-avoid">
```
```css
.toc ol { column-rule: 1px solid var(--color-border); }
```
- `columns-1` / `lg:columns-2`：Tailwind 映射到 `columns:1` / `columns:2`（注意是 `columns` 不是 `column-count`）
- `gap-x-8` 在多栏下映射到 `column-gap`，正好是两栏间距
- `break-inside-avoid`：防止单个目录项被栏边界切断
- `column-rule` Tailwind 无现成工具类，必须写在组件 `<style>` 里；
  用 `var(--color-border)` 而非硬编码颜色，这样跟随深色模式切换

**注意**：CSS columns 默认 `column-fill: balance`，两栏高度会被均分。
想要「先填满左栏」的真实纵向排列需 `column-fill: auto` + 固定高度，
但目录高度不确定，所以保持默认 balance 即可。

## ⚠️ 组件样式验证的正确位置（我踩了两次）

Astro 会把组件 `<style>` **内联进页面 HTML 的 `<head>`**（带 `data-astro-cid-*` scope 属性），
**不会**产出到 `dist/_astro/*.css`。所以在 CSS 文件里搜 `.toc ol` / `column-rule`
一律搜不到，会误判「样式没生成」。

正确查法：
```bash
node -e "const h=require('fs').readFileSync('dist/posts/xxx/index.html','utf8');
console.log(h.match(/<style>[^]*?<\/style>/g).join('\n'))"
```
只有全局样式（`src/styles/*.css`）才进 `dist/_astro/*.css`。

## TOC 第四轮迭代：三级层级样式区分

原先第 2/3 层只有缩进+ 字重区分，视觉几乎无差别。
用户从 4 个方案中选定 **D：竖线分级 + 间距分组**
（另两个决定：第 2/3 层文字同色、样式固定不随实际层数动态降级）。

```astro
{items.map(({ slug, text, level }, index) => {
  const isFirst = index === 0;
  return (
    <li class="break-inside-avoid">
      <a class:list={[
        "hover:bg-muted hover:text-accent block border-s py-1.5",
        "pe-2 transition-colors",
        level === 0 && "border-s-foreground border-s-[3px]",
        level === 1 && "border-s-muted-foreground border-s-2 ps-9",
        level === 2 && "border-s-border border-s ps-14",
        level === 0 ? "ps-5" : "",
        level === 0 && !isFirst && "mt-3",
        level === 0
          ? "text-foreground text-sm font-medium"
          : "text-muted-foreground text-sm",
      ]}>
```

三个关键点：
- **竖线用 `border-inline-start`**：`border-s-[3px]` / `border-s-2` / `border-s`（默认 1px）
  配 `border-s-foreground` / `-muted-foreground` / `-border` 三档颜色，深色模式自动跟随。
- **分组留白必须排除首个**：靠 `isFirst` 判断，否则开头多一块空白。验证方式是
  `mt-3` 数量应恰好等于「顶层项数 − 1」。
- **`hover:border-s-accent` 不存在**！Tailwind 只有 `hover:border-accent`（全四边），
  没有单边框的 hover 变体。解法：写进组件 `<style>`：
  `.toc a:hover { border-inline-start-color: var(--color-accent); }`

### 实际层数分布（供后续参考）

层级动态计算（`level = depth - minDepth`），各文章实际不同：
- Linux：2 层（29 项 = 5 L1 + 24 L2）
- 学习笔记：3 层齐全（14 项 = 3 + 6 + 5）
- 魔神之后：3 层（42 项 = 1 + 11 + 30，但只有 1 个顶层，L1 样式几乎看不到）

因为 minDepth 动态归一化，**大多数文章实际只有 2 层**。

## TOC 第五轮迭代（最终版）：纯竖线分级 + 字重递减

用户决定**去掉分组留白**，只保留竖线分级，并让三种标题字重依次递减。
第四轮的 `mt-3` / `isFirst` 逻辑已全部删除（`isFirst` 删掉后 map 回调恢复单参数）。

```astro
{items.map(({ slug, text, level }) => (
  <li class="break-inside-avoid">
    <a class:list={[
      "hover:bg-muted hover:text-accent block border-s py-1.5",
      "pe-2 transition-colors",
      // 竖线分级：3px 实色 / 2px 中色 / 1px 浅色
      level === 0 && "border-s-foreground border-s-[3px]",
      level === 1 && "border-s-muted-foreground border-s-2",
      level === 2 && "border-s-border border-s",
      // 缩进
      level === 0 ? "ps-5" : level === 1 ? "ps-9" : "ps-14",
      // 字重依次递减 500 / 400 / 300
      level === 0 && "text-foreground text-sm font-medium",
      level === 1 && "text-foreground text-sm font-normal",
      level === 2 && "text-muted-foreground text-sm font-light",
    ]}>
```

最终三级维度（每层两个信号：竖线粗细+颜色、字重，另有缩进）：
| 层级 | 竖线 | 字重 | 色 | 缩进 |
|---|---|---|---|---|
| L1 | 3px foreground | 500 medium | foreground | ps-5 |
| L2 | 2px muted-foreground | 400 normal | foreground | ps-9 |
| L3 | 1px border | 300 light | muted-foreground | ps-14 |

**「依次递减」要用 500/400/300 三级**（font-medium / font-normal / font-light），
第 2、3 层都用 `font-normal` 不算递减。

### ⚠️ 字体体系半废弃（影响字重效果，重要）

- `src/layouts/Layout.astro` 第 47-63 行**整个 `<Font>` 块被注释掉了**（含中文苹方）
- `src/styles/theme.css` 只注册了一条 `@font-face`，且
  - 路径写错：`/public/fonts/...` 应为 `/fonts/...`（public 是构建根，源码里写/public 会 404）
  - 只声明 `font-weight: 300`，其他字重没注册
  - `unicode-range: U+0000-00FF` 只覆盖拉丁字符，中文走系统字体
- 但 `public/fonts/` 下**字体文件其实都存在**（5 个字重：
  Light 300 / Regular / Medium / SemiBd / XBlack），只是没被正确引用

结论：**当前 `font-light`(300) 在中文目录里没有真正生效的字体**，
会回退到系统中文字体的 300（多数中文字体无 300，浏览器会合成或落到 400）。
要真正看到三级字重递减，需修好字体加载（改路径 + 补多字重 `@font-face`）。

## TOC 第六轮迭代（当前最终版）：补上第三层可见竖线 + 字重简化

用户反馈「第三层没有竖线」。排查结论：**类名和 CSS 其实都生成了**，
但 `border-s`（1px）+ `--border`（浅色模式下 `#ece9e9`）在屏幕上几乎不可见，
所以看起来像没有。修复：第三层改用 `2px` + `muted-foreground/50` 透明度。

同时用户说「字号不用那么关心，一级标题加粗就差不多了」，
所以**砍掉第三层字重**：L1 用 `font-medium`，L2/L3 都用常规字重。

```astro
// 竖线分级：4px / 3px / 3px，颜色依次变浅
level === 0 && "border-s-foreground border-s-[4px]",
level === 1 && "border-s-muted-foreground border-s-[3px]",
level === 2 && "border-s-muted-foreground/50 border-s-[3px]",
// 缩进
level === 0 ? "ps-5" : level === 1 ? "ps-9" : "ps-12",
// 文字：仅一级标题加粗
level === 0
  ? "text-foreground text-sm font-medium"
  : "text-muted-foreground text-sm",
```

**最终三维区分**（第七轮：用户嫌太细，整体加粗）：
| 层级 | 竖线 | 缩进 | 字重 | 色 |
|---|---|---|---|---|
| L1 | 4px foreground | ps-5 | **500** | foreground |
| L2 | 3px muted-foreground | ps-9 | 常规 | muted-foreground |
| L3 | 3px muted-foreground/50 | ps-12 | 常规 | muted-foreground |

### 经验教训：1px + 浅色边框在浅色主题下等于不可见

Tailwind 的 `border-s`（无后缀）= 1px，依赖 `--tw-border-style`（`@property`
里 `initial-value: solid`，所以技术上会渲染）。但配 `--border`（浅色模式
`#ece9e9`、深色模式 `#ab4b08`）在屏幕上根本看不见。
**做多层级视觉分级时，最细一档也要给 2px + 半透明色**，否则等于没有。

另外：`border-s-muted-foreground/50` 生成的规则是
`color-mix(in oklab, var(--muted-foreground) 50%, transparent)`，
Tailwind v4 对 CSS 变量色的透明度支持是正常的（之前 `bg-accent/8` 那次失败
是因为 `accent` 虽是变量但透明度组合写法不同，与本例无关）。

## Bash 里查 CSS/HTML 的正确做法（别再踩）

```js
const css = require("fs").readFileSync(cssPath, "utf8");

const start = css.lastIndexOf("}", i) + 1;
console.log(css.slice(start, css.indexOf("}", i) + 1));
```
CSS 文件名带 hash，用 `ls -t Layout.*.css | head -1` 取最新。
